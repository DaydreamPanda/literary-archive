# 私人文学档案馆 · Novel Site 改造补丁 v3

本压缩包是以 [xingzihai/novel-site](https://github.com/xingzihai/novel-site) 为基础的**差异补丁**，包含新的前台页面和附加的 Cloudflare Pages Functions。**不是单独可部署的完整网站**。原项目使用 **AGPL-3.0**，必须保留原项目的 LICENSE、署名并遵守其开源许可。此补丁针对 2026 年 11 月核对过的 Novel Site API 结构设计，实际生产部署仍需测试。

## v3 修改内容

1. 作者介绍卡片右边新增独立的「其他平台」栏。Pixiv、X、AO3 在未填写地址时以“待设置”形式示意；填写后变成真正的外部链接。通过 `/archive-admin.html` 修改。
2. 作品目录改为**大章 → 小节**：同一个大章下面有 2 节或更多，点击大章展开小节；只有 1 节时，直接打开其正文。正文和番外分别排列。通过 `/archive-structure.html` 维护，不用编辑 GitHub 文件。
3. 阅读页增加**无账号、无昵称、单层匿名评论**。所有评论对外统一显示「读者评论」，没有回复和读者个人主页。新留言进入待审核队列，只有站点所有者批准后才会公开。通过 `/archive-moderation.html` 审核，也可以拒绝或删除。
4. 阅读页新增**每节点赞总数**，全站读者看到同一个数字。无需登录，浏览器首次访问会收到匿名随机 Cookie，每个浏览器对同一节只能点赞一次，也可取消点赞。数据保存在 Cloudflare D1。
5. 保留 v1 的 18+ 提示、米白纸张主题、夜间模式、标签搜索、章节阅读、前后章节跳转、封面显示、作者个人资料、站内正文编辑（使用 Novel Site 原后台）。

## 本地预览

解压补丁包，直接双击 `index.html`。网页在 `file://` 环境会自动显示**演示作品**。

- 演示中《盛京旧梦》第一章有 4 节，第二章只有 1 节，第三章有 2 节，还有独立番外。请点击作品进入系列页体验展开。
- 演示点赞数与评论都只保存在当前浏览器中，正式版点赞数量来自 Cloudflare D1。
- 演示评论只保存在当前浏览器的本地存储中，若浏览器禁用本地存储，则只在当前页面会话内保存，**不会上传到网站**。
- 本地文件不能访问 D1、R2、云端 API，因此不能保存真实小说、章节结构或进行线上评论审核。
- 若直接双击 HTML 受浏览器本地文件安全策略影响，请在可用的本地静态服务器中打开 `index.html?demo=1`。

## 正式部署（在原 Novel Site 项目上覆盖）

1. 先下载/克隆原项目 `https://github.com/xingzihai/novel-site`，按原项目 README 配置 Cloudflare Pages、D1、R2 和管理员身份。
2. 备份原项目的 `index.html`、`book.html`、`read.html` 和数据。将此 ZIP 内**所有文件和子目录**复制到原项目根目录，在同名文件冲突时覆盖指定前台文件，保留原项目其他文件、`admin.html`、`schema.sql`、`style.css`、`functions/api/_utils.js` 等。
3. 不要用这个补丁替换整个 `functions` 文件夹；只合并补丁中新增的七个 API 文件。原作者后台和数据库初始化仍依赖原项目。
4. 在 **Cloudflare Pages 项目设置 → Variables and Secrets（环境变量与密钥）** 中新增 Secret：`ARCHIVE_COMMENT_SECRET`（同时供评论限流与匿名点赞使用），值为独立生成的随机长字符串（至少 24 字符）。推荐运行 `openssl rand -hex 32` 生成。**不要把密钥写到 GitHub 或公开前端 JS 中**。添加后重新部署，让 Pages Functions 获取该环境变量。
5. 访问 `/admin.html` 登录 Novel Site 原有超级管理员账号。
6. 访问 `/archive-admin.html` 编辑作者笔名、个人资料、公告和 Pixiv/X/AO3 真实链接。
7. 在 `/admin.html` 创建作品、上传封面、添加标签和实际正文小节。在 `/archive-structure.html` 选择该作品，将应属于同一大章的小节的「所属大章」设置为相同名字，填写各小节标题，保存。
8. 读者进入正文页后，爱心旁会显示当前小节的全站点赞总数，点击爱心可点赞，再点一次取消。
9. 读者可以在正文页提交匿名评论。新评论默认不公开；进入 `/archive-moderation.html` 审核，批准后出现在相应的正文页。

### 章节结构例子

Novel Site 原后台的每个“章节”在改造后代表**一份可独立阅读的正文内容**，可以当作一个小节：

| 原 Novel Site 章节 | 所属大章（后台填写） | 小节标题（后台填写） | 分类 |
| --- | --- | --- | --- |
| 原始正文 101 | 第一章 北风入盛京 | 第一节 风起 | 正文 |
| 原始正文 102 | 第一章 北风入盛京 | 第二节 故人 | 正文 |
| 原始正文 103 | 第一章 北风入盛京 | 第三节 暮雪 | 正文 |
| 原始正文 104 | 第一章 北风入盛京 | 第四节 夜话 | 正文 |
| 原始正文 105 | 第二章 旧人赴前尘 | 留空即可 | 正文 |
| 原始正文 106 | 番外 · 灯下书 | 留空即可 | 番外 |

同大章的多个正文单元在页面中合并成可展开的卡片。只有一个单元的章节会直接打开正文。后台直接修改原章节的文字依然有效，映射不会覆盖正文。**如果你把单个现有章节拆分成四节，需要先在原管理员后台创建四个独立的正文单元，然后再设置它们的所属大章。**

### 匿名评论的使用与限制

- 读者无需账户、昵称或邮箱；显示标签固定为「读者评论」，完全没有嵌套回复。
- 评论 2 到 1000 字，拒绝直接张贴网址，公开前需作者审核。
- Cloudflare 服务端为限制滥用，使用随机密钥对访问 IP 做单向哈希，保存哈希用于频率限制；**没有向读者展示 IP，也不会存原始 IP**。默认同一来源至少间隔 2 分钟，每 24 小时最多 5 条。它无法严格保证“每个人只能评论一次”，也无法彻底阻止换 IP 的刷屏。
- 默认按最新显示前 60 条已批准评论。审核后台每个状态显示最近 100 条。
- D1 的评论表和索引会在首次调用评论接口时自动创建，不需要手动执行额外 SQL 文件。
- 如果尚未设置 `ARCHIVE_COMMENT_SECRET` 或 Cloudflare 未提供真实的 `CF-Connecting-IP`，实际提交将被拒绝。安装完成后应先测试评论的完整审核流程，再对外开放。
- 部署时需要确保隐私声明、评论管理以及年龄提示符合你的运营地区和访问者所在地适用要求。

### 匿名点赞的使用与限制

- 点赞按正文小节独立统计，跨设备显示共享数量。
- 每个浏览器首次进入正文页时会获得随机 HttpOnly Cookie，服务端仅存该 Cookie 的加盐哈希值。Cookie 不包含姓名或邮箱。
- 同一浏览器重复点击不会重复累计点赞，可以取消点赞。清除 Cookie、切换浏览器或更换设备仍可能再次点赞，因此无法保证一位自然人只能点赞一次。
- 点赞与评论共用 `ARCHIVE_COMMENT_SECRET`，未设置该密钥时可以读取已有点赞数，但无法新增点赞。
- D1 点赞表首次访问点赞接口时自动创建，正式上线前请验证数据库绑定与跨设备计数。

## 注意事项

- 目前首页没有真实平台链接时只是**不可点击的占位标签**。需要你本人填写 Pixiv/X/AO3 的 URL，绝不会自动猜测账号。
- 原 Novel Site 的书籍、章节 API 仍是数据来源。图片封面继续取自 `/api/covers/{bookId}`；没有实现每一节的独立封面或独立简介。
- 站点上方的年龄确认只是**用户自愿确认**，不能代替法律要求的年龄验证。
- 点赞总数使用 D1 持久化，按浏览器 Cookie 去重，仍无法防止恶意用户清除 Cookie 后重复点赞。
- 本补丁没有移植原阅读页的翻页模式、批注、举报、书签和离线增强功能。如需这些功能，后续应重新整合。
- 正式上线前建议添加 Cloudflare Turnstile 或更强的反滥用措施，并测试安全性、移动端与数据备份。
- 成人文字及封面是否允许由托管商的现行服务条款和当地法律决定。建议第一版先使用不露骨的封面。
- 未完成真实 Cloudflare 环境端到端测试，请先在测试项目发布，确认后台权限、D1 数据、评论审核和作品目录正常。
