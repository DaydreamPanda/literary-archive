# 熊猫头文学档案馆：跨作品移动章与节（第 1 版）

## 功能

- 章节工作台的作品选择器分组展示 **系列作品 / 单篇作品**，两类作品均可管理、编辑、导出、排序。
- 点击多节的大章，在右侧使用“移动整章到其他系列或单篇”：会同时搬动下面所有小节。
- 点击具体小节，使用“移到其他系列 / 独立成单篇”：只搬动这一节。
- 目标位置：① **新建单篇作品**，自动创建新书并赋予“单篇”Tag；② **其他已有系列**，可以设置目标大章名，若同名可加入现有大章。
- “编辑作品资料”可修改当前系列或单篇的作品标题、作者、简介；正文编辑器仍可设置封面和 Tag。
- 如果搬走的是原作品的最后内容，可以手动勾选“自动下架空作品”。下架可在原后台恢复。

## 数据保留原则

迁移执行 D1 `chapters.book_id` 变更，原章节 ID 不变，保留正文、单节封面、独立 Tag、匿名评论、点赞和章节阅读统计，以及旧阅读页的 URL。源/目标系列的章、节分组和阅读顺序同步更新。旧有“上下节”进度条依赖章节 ID/目录，也会随新归属刷新。

新建单篇时，会继承来源作品适用的 Tag，增加“单篇”；若原章节有独立封面，复制出**新的封面资源**供单篇作品卡使用，避免图片资源共用导致删除互相影响。如果章节无封面，尝试复制来源系列封面。

**注意：** 已累计的历史 *书籍级* 访问统计仍留在原系列，章节自身的阅读统计随章节保留。迁移后源作品如果变空，默认仍保留（可选择自动下架）。

## 安装顺序

1. 在作者后台先执行“导出备份”，另留一份从 Pixiv 导出的 EPUB 原始文件。
2. 下载 ZIP 并解压。请上传 ZIP 内的代码文件，**不要把 ZIP 压缩包原样上传到 GitHub**。
3. GitHub 项目： `DaydreamPanda/literary-archive`，用 DaydreamPanda 账号操作。上传/替换根目录的：
   - `archive-structure.html`
   - `archive-structure-admin.js`
   - `archive-structure-studio.css`
4. 请保留文件夹层级，再添加：
   - `functions/api/admin/archive-transfer.js` （**新增**）
   - `functions/api/archive-structure.js` （**覆盖**，取消目录 30 秒缓存）
5. Commit 到 `main`，等 Cloudflare Pages 生产部署变绿。
6. 打开 `https://literary-archive.pages.dev/archive-structure.html`，必须先登录原作者后台（超级管理员）。

## 建议验收

1. 在工作台下拉框确认系列和单篇作品两个组都出现。
2. 在一个有两节的章选“大章”→“移动整章”，测试目标选择框，再取消（检查无数据改变）。
3. 选取一个测试节，先移入另一本系列并查看系列目录，确认标题、封面和上下章顺序。
4. 再把这节移出成新单篇，确认它出现在首页的“单篇作品”，且原章节 URL 仍正常。
5. 测试“编辑作品资料”的书名/简介，核查作者后台、系列、单篇和读者页。

## 安全说明与限制

- 移动操作要求超级管理员身份，必须在弹窗中两次确认，不能在未保存目录修改时执行。
- 实际的章节跨书迁移会触及线上数据。建议先用测试篇目验证，再处理重要文章。
- 后端迁移通过 D1 批处理同步源/目标分组及顺序，减少部分成功的数据不一致风险；新建单篇的建书步骤在批处理前进行，如后续迁移失败会尝试清理未使用的空书。
- 本地完成了浏览器交互与 SQLite SQL 模拟测试，未在你的真实 Cloudflare 生产 D1 数据上实际操作。发生异常不要重复点击，先刷新页面核对章节归属。
- 一次只能移动同一个大章的全部节，或单个小节；不支持跨作品拖拽，不涉及复制或合并正文段落。

## 出问题时

- 如果系列页显示旧目录，强制刷新浏览器。新版 `/api/archive-structure` 已关闭缓存。
- 遇到“章节归属变化”，先刷新工作台，不要连续重复迁移。
- GitHub 可在提交历史回退代码。D1 内容需使用你自行导出的备份回滚，GitHub 回退不会逆转已完成的数据库迁移。
